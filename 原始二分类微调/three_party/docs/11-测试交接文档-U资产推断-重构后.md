# CipherForge 测试交接文档（重构后 · U 资产推断）

> 适用版本：**重构后**四进程 CipherForge（U / M / S 直连 + 独立主控台 coordinator）
> ——U 只发 H_U/C_U 给 M、PIR 直连 S；M→S 直发 H_M；S→M 直推 s_S；验证只回类别 logits。
> 测试任务：ClinVar 变异致病性二分类（备选 BioTriplex-7）
> 编制日期：2026-08-27

## 0. 文档目的

本文档定义重构后**压缩版**测试（仅 1 个测试项）的实验类别、指标口径、数据来源
（复用/重测）、使用的数据集与模型，供执行者据此实施并产出可直接写入《作品报告》
的数据。核心目标：回答"用户方 U 能否通过其拥有的信息，推断得到模型方 M 每步更新
的 LoRA 权重，以及服务方 S 的任务头 V"。

与旧版《作品报告测试部分.pdf》的关系：

- **方法口径、判读规则、与消息路径无关的结构性结论**可复用；
- **旧 M-1（U 模型提取）的数值必须弃用**（其假设的"top-1+置信度黑盒查询"既不符
  合旧实现，也不符合重构后架构）；由本方案测试项 1 替代；
- **任务头/主干权重推断此前从未测试**，本方案为新增；
- 性能数值因进程拓扑改变必须重测；精度数值建议重测（详见第 9 节）。

## 1. 资产与隐私声明（重构后拓扑）

| 资产 | 内容 | 归属 | 隐私属性 |
|---|---|---|---|
| 数据集 | ClinVar 致病性 QA（Yes/No 二分类）train/val/test = 10000/9708/10000 | U（数据方） | **私有** |
| 模型 | TinyLlama-1.1B-Chat-v1.0（22 层，hidden=2048，vocab=32000） | U/M/S 各持分片 | **私有** |
| U 分片 | embed + decoder 0~10 + PIR 客户端 + 掩码池 | U | 私有 |
| M 分片 | decoder 11~21 + final norm + LoRA（r=8, α=16, dropout=0.05）+ sk_M | M | 私有 |
| S 分片 | lm_head V（32000×2048，冻结）+ 密文库 D[y]=Enc(−V_y) | S | 私有 |
| 标签 y / 输入 x | 只存在于 U 节点 | U | 私有 |
| 主控台 coordinator | 独立进程：不持有数据、不中转张量，仅控制面 + checkpoint | 独立 | 可信控制面 |

威胁模型：

1. **主模型**：U 半诚实（honest-but-curious），按协议执行训练，仅分析协议实际发
   给它的消息（p_yes、类别 logits、PIR 密文、自己的 H_U 与标签）；
2. **扩展模型（接口级）**：U 额外利用无鉴权 HTTP 接口，用任意 H_U 主动查询
   `trunk_forward` / `val_forward` 获得 `(H_U → 类别 logits)` oracle——这是实现层面
   的攻击面，与半诚实主结果**分开报告**；
3. M/S 半诚实且不串通；V 对 M/U 保密（head-confidentiality 假设）；不使用公开
   辅助数据做攻击训练（**V 公开变体仅作边界敏感性分析**，不属于协议假设）。

安全目标边界：不承诺抗两方串通、抗 V 本身公开、抗主动偏离协议的恶意行为。

## 2. 符号约定

| 符号 | 含义 |
|---|---|
| x, y | 私有输入、私有标签（Yes/No） |
| H_U | U 侧切分激活值（B×S×2048），DP 噪声注入点（U 自己知道噪声） |
| h = H_M | M 侧输出（B×S×2048），**M→S 直发，U 不可见** |
| V | S 持有的 lm_head（32000×2048），v_yes / v_no 为对应行 |
| z_cls | 验证期类别 logits（B×C，C=2），= [h·v_yes, h·v_no]，U 可收到 |
| p_yes | 训练期监控标量 = σ(h·(v_yes − v_no))，U 可收到（经 M 转发） |
| s_S = a_t − r_t | S 直推 M 的明文份额，**U 不可见** |
| C_U = Enc(−v_y + r_t) | U 构造并发给 M 的掩码密文（U 知道 y、r_t，无 sk） |
| W_M(t) | M 在第 t 步的 LoRA 参数（真值，仅实验评估端记录） |
| ΔW = B·A | LoRA 有效更新（规避 A/B 秩空间等价类） |
| oracle | `H_U → (z_cls / p_yes)` 的函数，U 可获得其输入输出对，但不知道中间 h |

## 4. 数据集与模型（正式口径）

### 4.1 数据集（主口径：ClinVar）

- **名称**：ClinVar 变异致病性二分类 QA（答案 Yes/No）
- **划分**：train 10000 / val 9708 / test 10000（按基因切分，互不重叠，pos_rate≈0.5）
- **路径**：服务器 `/root/CipherForge/CipherForge-ClinVar/three_party/party_u/data/qa`
- **序列长度**：max_seq_length=128
- **用途**：T1 攻击测试在此任务上执行；与 09 实验报告的精度基线（test AUPRC
  0.7779 等）可直接衔接
- **备选**：BioTriplex-7（7 类 a)~g)，train/val/test=431/90/83）——切换
  `task_type=biotriplex7` 即可，指标口径不变；若采用须在报告中注明数据集差异

### 4.2 模型与加密参数

- **基座**：TinyLlama-1.1B-Chat-v1.0（快照 `fe8a4ea1…`）
- **切分**：u_layers=11 / m_layers=11；LoRA r=8、α=16、dropout=0.05，只挂 M 侧
- **加密**：BFV poly_degree=4096、plain_bits=30、scale=10000；密文库 32000×2048
- **PIR**：块 PIR（block=64、fake_ratio=0.25）与 RMS-PIR（partition=200、lam=16）
  各跑一组，全矩阵保持一致并在报告注明
- **DP**：dχ 多元 Laplace，默认 α=0.03、η₀=1500、β=0.5（与部署一致）。
  **本攻击与 DP 挡位无关**：U 知道它自己注入的噪声，可还原干净 H_U；DP 保护的是
  U 的样本（防 M/S），不保护 M/S 的资产（防 U）

### 4.3 参照基线

| 基线 | 定义 | 用途 |
|---|---|---|
| 随机基线 | V 行恢复率 1/32000、RE_F≈1、方向余弦≈0 | "零泄露"参照 |
| 密文对照（U1b） | 只用 PIR 密文恢复 V | 证明密码层未被攻破 |
| V 公开变体（敏感性） | 假设 U 已知 V，只拟合 W_M | 边界分析，非协议假设 |

基础配置：task=clinvar、batch_size=4、max_seq=128、max_epochs=1（机制验证跑

| 运行 | 内容 | 步数 | 说明 |
|---|---|---|---|
| R1 | T1 主运行（块 PIR，被动 + 主动 oracle） | 200 | 攻击数据采集 + 离线攻击 |
| R2 | T1 主运行（RMS-PIR） | 200 | 与 R1 对照，验证 PIR 变体不影响结论 |

## 6. 测试项 1 设计（U 方资产推断攻击）

**攻击者**：U。主模型为半诚实（只用协议发给它的消息）；扩展模型允许主动调用
无鉴权 `trunk_forward`/`val_forward` 获取 oracle（分开报告）。

### U1a 协议信息面审计（前置子步，静态 + 抓包）

- **做法**：在 U 节点 HTTP 客户端打只读记录点，跑 50 步训练 + 1 次验证，导出 U
  实际收到的全部消息（字段、形状、字节数）；
- **指标**：消息清单；是否存在 H_M / s_S / 全词表 logits / lora_state（布尔）；
  U 可派生量（能否算出 a_t、能否算出 h）；
- **判读**：四类明文张量全部为"否" ⇒ 通过，T1 攻击输入与协议假设一致；任一为
  "是" ⇒ 通道未关死，后续攻击结论另论（并立即修复）。

### U1b 密文通道对照

- **做法**：U 只使用 PIR 密文行、自构造 C_U、y、r_t、pk，尝试任何统计方法恢复
  V 行（密文差分、猜测打分）；
- **指标**：行恢复率（随机基线 1/32000）、RE_F(V)；
- **判读**：≈随机 ⇒ PRESERVED（BFV 语义安全有效）。

### U1c 复合 oracle 恢复 V

- **做法**：
  1. U 收集 `(H_U, z_cls)` 与 `(H_U, p_yes)` 对：训练期被动收集 + 主动用任意 H_U
     （随机高斯/基向量）反复查询（查询量扫描 {0, 1k, 10k, 50k}）；
  2. 攻击①盲恢复：把 H_U 误当 h 做最小二乘（验证"缺 h 导致方法失效"）；
  3. 攻击②联合拟合：同构 student 同时拟合 (Ŵ, V̂) 匹配全部观测；
  4. 与 S 侧真值 V 比较（真值仅评估端使用）；
- **指标**：RE_F(V)、行余弦、组合模型功能一致率（student vs 真模型 P(Yes) 一致率、
  logits 相关）、查询复杂度曲线；
- **判读**：
  - RE_F 高（>0.5）且行余弦≈0 ⇒ **PRESERVED**（V 行不可推断）；
  - 参数误差大但功能一致率高 ⇒ **PARTIAL**（仅行为级克隆组合模型，不能分离 V）；
  - RE_F<0.01 ⇒ **LEAK**。

### U1d 复合 oracle 恢复 M 每步权重

- **做法**：
  1. 实验方（非 U）在 M 侧每步记录真值 W_M(t)（仅评估）；
  2. U 用同一批 `(H_U, z_cls)` 对，对每个目标步 t 拟合 student LoRA Ŵ(t)（V 未知
     变体联合拟合；V 公开变体固定 V 只拟合 Ŵ，标为敏感性分析）；
  3. 形成逐步序列 Ŵ(t) 并与真值序列比较；
- **指标**：每步 RE_F(ΔŴ(t), ΔW(t))（ΔW=B·A 复合）、更新方向余弦
  `cos(ΔŴ_t, ΔW_t)`、轨迹相关（时间相关性）、功能一致率；
- **判读**：
  - 每步 RE 高、方向余弦≈0、轨迹相关≈0 ⇒ **PRESERVED**（每步精确权重不可推断；
    U 只能感知行为随步变化，不能还原权重）；
  - RE→0 或方向可追踪 ⇒ **LEAK**；
  - 功能一致率高但 RE 高 ⇒ 行为级克隆（残余风险，如实报告）。

## 8. 指标定义与判读（总表）

| 指标 | 计算 | 机会水平/安全参考 | 泄露判据 | 反映什么 |
|---|---|---|---|---|
| 信息面清单 | U 收到消息逐字段审计 | 不含 H_M/s_S/全词表 logits/lora_state | 含任一项即协议失守 | U 的信息集是否与论文一致 |
| 行恢复率 | 恢复 V 行与真值匹配 | 1/32000 | ≫随机 | 密文通道是否泄露 V |
| RE_F(V) | ‖V̂−V‖_F/‖V‖_F | ≈1 | <0.01 | V 是否可精确恢复 |
| 行余弦 | mean cos(V̂_i, V_i) | ≈0 | >0.999 | 恢复方向质量 |
| RE_F(ΔW) | 每步 LoRA 有效更新相对误差 | ≈1 | <0.01 | M 每步权重是否可恢复 |
| 更新方向余弦 | cos(ΔŴ_t, ΔW_t) | 0 | >0.9 | 每步更新是否可追踪 |
| 轨迹相关 | Ŵ(t) 与真值序列时间相关 | 0 | >0.9 | 权重轨迹是否可还原 |
| 功能一致率 | student vs 真模型预测一致率 | 二分类≈0.5 | >99.9%（行为级克隆） | 行为级提取边界 |
| 查询复杂度 | 达到某一致率所需主动查询数 | — | 越小越危险 | oracle 攻击成本 |

判定标签：**LEAK**（任一参数误差趋零或方向可追踪）/**PARTIAL**（参数误差大但功能
一致率高，行为级克隆）/**PRESERVED**（全部贴近机会水平）。

## 10. 执行流程（每 run）

1. 确认环境（RTX 5090、PyTorch+SEAL 依赖、私有模型/数据路径）；
2. 生成 run 配置（基于 `coordinator/three_party_config.json` 或 RMS 变体，改
   task_type/步数/seed/PIR 模式）；
3. 启动四进程（U:9001 / M:9002 / S:9003 / coordinator），初始化 BFV/PIR/DP；
4. **U1a**：U 侧旁路记录器抓包（消息白名单检查）；
5. 训练 N 步，旁路采集（不干扰训练）：
   - U 侧：真实 input_ids、标签、干净 H_U、收到的 p_yes / 类别 logits / 密文行；
   - M 侧（实验评估端）：每步真值 W_M(t)、g_absmax/g_meanabs；
   - S 侧（实验评估端）：V 真值哈希、a_t 快照（仅验证用）；
6. 主动 oracle 查询：对 trunk_forward / val_forward 发任意 H_U，收集
   (H_U → z_cls) 对（查询量按矩阵）；
7. 离线攻击：U1b 密文对照、U1c 联合拟合、U1d 逐步权重拟合；
8. 输出 per-run 报告（指标表 + verdict + 图）。

## 11. 采集与落盘约定

每 run 一个目录：

```
run_T{1,2}_{block,rms}_seed42/
  config.json               # 实际生效配置
  u_message_capture.jsonl   # U 收到的每条消息（字段/形状/字节），U1a 审计
  oracle_pairs.npz          # (H_U, z_cls, p_yes) 对（被动+主动）
  ciphertext_samples.bin    # U1b 密文行样本（小批量）
  true_weights_step.npz     # M 侧 W_M(t) 真值（仅评估端，严禁进入 U 进程）
  v_hash.json               # S 侧 V 真值哈希（仅验证用）
  report.md                 # 指标汇总 + verdict
```

> **隔离铁律**：V 与 W_M(t) 真值只存在于实验评估端进程，绝不写入 U 节点日志或
> 通过 U 的接口返回，否则实验自证失败。

---

## 12. 交付物

- 信息面审计表（U 收到的消息清单 + 四类明文张量布尔判定）；
- T1 指标表（RE_F(V)、行余弦、RE_F(ΔW)、更新方向余弦、轨迹相关、功能一致率、
  查询复杂度），按半诚实 / 主动 oracle 分列；
- verdict 汇总（LEAK / PARTIAL / PRESERVED，逐项给出依据）；
- 若需性能章节：TinyLlama/ClinVar 版通信/耗时/内存全套（重测）。

---

## 13. 风险与注意事项

1. **Ground truth 隔离**：V/W_M 真值仅评估端可用，严禁进入 U 进程（第 11 节）；
2. **主动 oracle 属于接口级攻击面**：`trunk_forward`/`val_forward` 无鉴权，U 可
   无限查询；主结论（半诚实）与接口结论分开报告；若要收紧，需给节点加 token 鉴权；
3. **不可辨识性机理**：U 观测只有 C 个线性投影且缺 h，精确恢复 V/W_M 在信息论上
   被否决；实验中若出现 RE→0，须排查是否意外泄露（如日志误打 H_M）；
4. **RMS/块 PIR 一致性**：全矩阵统一模式并注明；两种模式对 U 的观测面一致，
   结论应可互推；
5. **DP 挡位无关性**：U 知道自己的噪声，DP 不影响本攻击；报告中须写明，避免
   与 L-1 样本保护语义混淆；
6. **算力**：机制验证 100~200 步约 10~20 分钟/run；轨迹结论 1 epoch（625 步）
   约 30 分钟；完整 3 epochs 约 90 分钟（精度基准用）；
7. **结论口径**：任何 verdict 必须基于重构后新数据；旧文档 verdict 不得直接引用。
