# 05 · 兼容性与扩展性约定

> 通信方案可能调整、接口可能演进——本文档约定双方如何安全地变更，避免联调期"一改就挂"。

## 1. 版本协商

- 所有平台→节点请求携带 `protocol_version`（当前 `1.0`）。
- 节点在 `GET /v1/hello` 回报自己的 `protocol_version`。
- **主版本号不一致**（如平台 2.x 调节点 1.x）：平台总控台显示不兼容告警，不自动调用动作接口。
- **次版本号差异**（1.0 vs 1.1）：视为兼容，按"宽松读、保守写"处理。

## 2. 字段扩展规则（宽松读、保守写）

1. 任何一方收到**不认识的字段**：必须忽略，不得报错。
2. 新增可选字段：直接加，次版本号 +1，写入本文档附录。
3. 字段改名/删除/语义变更：主版本号 +1，并至少在两个版本周期内保留旧字段。
4. `capabilities` 是能力协商的唯一事实来源：平台调用 `fallback`/`eval` 前先检查能力集，缺失则在 UI 禁用对应入口而不是调用失败。

## 3. 新增协议动作 / 阶段

- 平台侧：在 `server/core/state.js` 的 `STAGES` 中登记（含执行方与动作 ID），无需改其他代码；本地模拟器按 `server/adapters/local.js` 的 `_act_<action>` 命名约定补充。
- 节点侧：在 `/v1/action` 中实现同名 `action`。
- 平台调用节点未实现的动作时，节点返回 `{ok:false, error:{code:501, message:"not implemented", retryable:false}}`，平台将该动作标记失败并允许跳过。

## 4. 新增评测项目

三种方式（按推荐排序）：
1. **页面注册**：评测台「+ 注册自定义测试」→ 写入 `data/fixtures/eval-presets.json`；
2. **直接编辑** `eval-presets.json`，追加 `categories[].tests[]` 条目；
3. 远程模式下节点在 `/v1/eval/run` 实现对应 `test_id`；未实现时平台自动回退到 `preset` 回放（若配置了预设结果）。

## 5. 通信内容/方式需要调整时

| 变更类型 | 处理流程 |
| --- | --- |
| 改消息字段名/结构 | 改 02/03 号文档 → 次版本号 +1 → 双方同日更新 → 联调验证清单跑一遍 |
| 改传输方式（如改 WebSocket、gRPC） | 新增适配器实现 `server/adapters/base.js` 的接口即可，平台核心不变；节点侧等价替换 |
| 改超时/重试 | 只改 `platform.config.json` 的 `timeout_ms`，无需改代码 |
| 临时联调 hack | 禁止直接改协议；在 `params` 里加临时字段（以 `x_` 前缀），稳定后再转正 |

## 6. 失败与重试语义

- `error.retryable = true`：平台允许在该方页面一键重试同一动作（幂等性由节点保证，`trace_id + stage + step + action` 为幂等键）。
- `retryable = false`：不重试，走 04 号文档预案。
- 节点崩溃恢复后：平台以 `/v1/hello` 探活确认，动作状态以平台侧 `completed_actions` 为准，节点应向平台索取当前 `trace_id` 与阶段（`GET /api/state` 可读）。

## 7. 安全边界声明（防扩展破坏安全叙事）

任何扩展不得引入以下行为，否则破坏三方安全模型：
- 把标签、原始文本、私钥、种子、掩码明文、输出头行明文写入任何跨方消息或日志；
- 让平台（笔记本）持有任何一方的私密资产；
- 在 U 侧返回完整 logits/预测分布（仅允许 top-K 监控）。
