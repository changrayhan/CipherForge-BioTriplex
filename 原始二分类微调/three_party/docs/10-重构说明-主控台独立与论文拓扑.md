# 10 · 重构说明：主控台独立，U/M/S 按论文拓扑直连

> 2026-08-27 重构。目标：让实现与 TriadFT 论文（`paper.tex` §Threat Model /
> §Technique Overview）的安全边界完全一致——**U 永不接触明文主干输出 H_M、
> 明文份额 s_S、全词表 logits，也拿不到 M 的 LoRA 权重**。

## 1. 原实现的问题（为什么必须改）

原三进程实现的拓扑是：

```
U（协调者进程，内嵌 PartyU + 全部数据）
  ├─ trunk_forward  → M 把 H_M 明文返回给 U
  ├─ head_forward   → U 把 H_M 转给 S
  ├─ share_compute  → S 把 s_shares = a_t − r_t 明文返回给 U
  ├─ grad_reconstruct → U 把 s_shares 转给 M
  └─ gather_checkpoint → M 把 LoRA 权重明文返回给 U（每 epoch）
```

因此 U 进程实际能接触：每步明文 H_M、明文 s_S（配合共享 PRG 种子可还原
`a_t = softmax(H_M Vᵀ)V`）、验证期全词表 logits（`logits = H_M Vᵀ` 可直接
最小二乘恢复 V）、以及 M 的 LoRA 检查点。这与论文"用户永远收不到主干输出和
输出头参数"（`paper.tex` L203-204）直接冲突。

## 2. 重构后的拓扑（4 进程，与论文一致）

```
                 ┌──────────────────────────────┐
                 │  Coordinator（独立主控台）     │  仅控制面：init / train_step /
                 │  不持有数据，不中转任何张量     │  run_eval / gather_checkpoint
                 └──────┬───────┬───────┬──────┘
                        │       │       │  control
        ┌───────────────▼──┐  ┌──▼─────────────┐  ┌▼───────────────┐
        │  U (party_u:9001) │  │ M (party_m:9002)│  │ S (party_s:9003)│
        │  (x,y)+底模+PIR   │  │ 主干+LoRA+sk_M   │  │ V+密文库        │
        └───┬───────────┬──┘  └──┬───────────┬──┘  └┬───────────┬───┘
            │H_U        │C_U     │H_M        │s_S    │PIR        │
            └───────────┼────────┴───────────┘       └───────────┘
                        └──────────────────────────────────────────┘
                              （所有数据面边均为直连）
```

数据面边（全部直连，不经过主控台）：

| 边 | 消息 | 实现动作 |
|---|---|---|
| U → M | H_U | `trunk_forward` |
| U → M | C_U = Enc(−V_y + r_t) | `grad_reconstruct` |
| M → S | H_M | `head_forward`（M 直发，响应只回 monitor p_yes） |
| M → S | 份额计算请求 | `share_compute`（控制） |
| S → M | s_S = scale·a_t − r_t | `receive_share`（S 直推，不经 U） |
| U ↔ S | PIR 查询/密文行 | `fetch_rows` / `rms_parity` / `db_download` |
| M → S | 验证期 H_M | `val_head`（S 只回类别 logits (B, C)，无全词表） |

## 4. 安全属性（重构后）

1. **U 无 sk_M**，PIR 拿到的 `Enc(V_i)` 仍是密文（BFV IND-CPA）；
2. **U 收不到 H_M**：M 的 `trunk_forward`/`val_forward` 响应不再含任何隐状态；
3. **U 收不到 s_S**：S 的 `share_compute` 直接把份额推给 M（`receive_share`）；
4. **U 收不到全词表 logits**：验证/测试只经 `val_head` 返回类别 logits (B, C)，
   无法线性反推 V；
5. **U 收不到 LoRA 权重**：`gather_checkpoint` 只由独立主控台调用（信任边界），
   U 节点无此接口；
6. 训练监控仅剩 `monitor_p_yes`（2 类 softmax 标量）与标量 metrics。

> 注意：仍依赖论文的 head-confidentiality 假设（V 不公开）。当前 ClinVar 部署
> 使用 TinyLlama 的公开 lm_head，V 本身可从 HuggingFace 获取；本重构消除的是
> **协议消息层面的泄露**，不是"V 是否公开"这一部署层问题。
