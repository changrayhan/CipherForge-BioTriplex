# 03 · 通信协议与消息格式约定

> 配套 02 号文档，约定事件类型、trace 规则、数据流边标记与脱敏规范。

## 1. 事件模型

平台以**事件流**驱动所有页面（SSE，`GET /api/stream`）。统一事件格式：

```json
{
  "id": 128,
  "ts": 1787045600000,
  "type": "pir",
  "stage": "BACKWARD",
  "party": "U",
  "trace_id": "task_20260818093000_ab12",
  "payload": { "msg": "PIR 查询已发出", "query_id": "q_ab12", "edge": "U->S", "bytes": 145408 }
}
```

| 字段 | 说明 |
| --- | --- |
| `type` | 事件类型，见下表 |
| `stage` | 所属阶段 ID（`INIT/DATA/FORWARD/BACKWARD/RECONSTRUCT/UPDATE/EVAL`） |
| `party` | 事件来源方 `U/M/S`；平台自身事件为 `null` |
| `trace_id` | 会话追踪 ID，一次微调会话唯一 |
| `payload.msg` | 一句人类可读描述（页面直接展示） |

## 2. 事件类型表

节点在 `/v1/action` 返回的 `events[]` 与 `/api/ingest` 推送中应使用以下 `type`：

| type | 语义 | 典型 payload 字段 |
| --- | --- | --- |
| `message` | 跨方消息（拓扑图触发粒子动画） | `edge`, `bytes`, `hash`, `msg` |
| `crypto` | 密码学操作 | `msg`, 参数（如 `poly_degree`）, `ct_hash` |
| `pir` | PIR 查询/响应 | `query_id`, `edge`, `bytes`, `pos` |
| `compute` | 本地计算（前向/反向/聚合） | `msg`, `step` |
| `data` | 数据装载/分词 | `sample_ids`, `batch` |
| `task` | 任务登记/产物汇总 | `hyper`, `checkpoint` |
| `monitor` | 训练监控（top-K、loss） | `loss`, `step` |
| `verify` | 梯度一致性校验 | `max_abs_error`, `rel_error`, `verdict` |
| `progress` | 长任务进度 | `progress`（0~1） |
| `guard` | 安全不变式提示 | `msg` |

平台自身事件（节点不需要产生）：`stage_begin / stage_done / stage_skip / action_begin / action_done / action_failed / session / fallback / fallback_node / eval_begin / eval_progress / eval_done / mode / drive / probe / node / state`。

## 3. 数据流边（edge）标记

拓扑图按 `edge` 字段驱动粒子动画，取值仅允许：

| edge | 语义 | 对应协议消息 |
| --- | --- | --- |
| `U->M` | 切线① | H_U、掩码密文 C_U |
| `M->S` | 切线② | H_M |
| `U->S` | PIR 通道 | PIR 查询 |
| `S->U` | PIR 通道 | PIR 响应、top-K 监控 |
| `S->M` | 份额通道 | 明文份额 s_S |
| `M->U` | 初始化 | 公钥 pk_M 分发 |
| `M->U`/`M->S`/`S->U`/`S->M` | 控制面 | 超参同步等 |

> RMS-PIR 模式下，U 与 S 之间的 hint 下载 / 子集 parity 请求/响应仍走 `U->S` /
> `S->U` 的 `pir` 事件边（action=`rms_parity`），与块 PIR 的 `fetch_rows`
> 复用同一事件类型，便于平台拓扑动画无改动复用。

## 4. trace 规则

- 平台发起会话时生成 `trace_id = task_yyyymmddHHMMSS_xxxx`。
- 节点本地日志、上报事件、评测结果均须携带同一 `trace_id`，平台按它聚合三方视图。
- 一次会话内 `step` 从 1 递增；训练循环外的阶段 `step = 0`。

## 5. 指标回传（metrics）

动作完成或进行中均可回传：

```json
{
  "comm": [ { "edge": "U->S", "bytes": 145408 } ],
  "loss": 1.9326,
  "grad_error": 2.1e-8,
  "step_ms": 12400
}
```

- `comm` 累计入总控台通信量与分通道统计；
- `loss` 追加到收敛曲线；
- `grad_error` 追加到保真度面板（期望量级 ≤1e-7，超过 1e-5 平台将告警提示复查定点编码）。

## 6. 脱敏规范

1. 上报内容仅允许：ID/哈希、尺寸、耗时、统计量、误差。
2. 禁止字段（平台强制替换为 `***`）：`raw_text, label, sk_M, prg_seed, mask_vector, head_row, weights`。
3. 建议节点侧日志同样脱敏后再落盘，便于现场直接展示日志证据。
