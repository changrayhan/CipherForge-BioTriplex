# 02 · 节点接口规范（U/M/S 服务器节点开发依据）

> **本文档交给三台服务器的开发同学。** 平台（演示笔记本）与三方节点之间通过 HTTP/JSON 通信。
> 每个节点（U、M、S）以同一套约定暴露接口；平台是唯一的调用方与展示方。
> 版本：protocol_version = `1.0`。兼容与扩展规则见 `05-兼容性与扩展性约定.md`。

## 0. 总览

```
演示笔记本（演枢台, :8600）                    服务器节点（U :9001 / M :9002 / S :9003）
┌──────────────────────┐  GET  /v1/hello    ┌────────────────────┐
│  阶段编排器            │ ─────────────────▶ │  节点服务            │
│  事件总线 / SSE        │  POST /v1/action   │  （TriadFT 协议实体） │
│  评测台               │ ◀───────────────── │                    │
└──────────────────────┘  POST /api/ingest   └────────────────────┘
        ▲                  （节点执行中主动推送进度事件）
        └──────────────────────────────────────
```

- 平台 → 节点：`GET /v1/hello`、`POST /v1/action`、`POST /v1/fallback/pretrained`、`POST /v1/eval/run`
- 节点 → 平台（可选但推荐）：`POST {platform}/api/ingest` 推送实时进度事件
- 全部请求/响应均为 `application/json; charset=utf-8`
- 所有响应统一信封：

```json
{ "ok": true, "...": "业务字段" }
{ "ok": false, "error": { "code": 400, "message": "人类可读错误", "retryable": true } }
```

## 1. GET /v1/hello —— 握手与能力协商

平台启动、每 15 秒探活、以及模式切换时调用。**超时 5s**。

**响应**

```json
{
  "ok": true,
  "node_id": "srv-u-01",
  "role": "U",
  "protocol_version": "1.0",
  "capabilities": ["action", "fallback", "eval", "ingest_push"],
  "assets": ["ClinVar 标注数据", "embed_tokens", "底部16层Decoder", "PIR客户端", "PRG种子σ"],
  "status": "idle"
}
```

| 字段 | 说明 |
| --- | --- |
| `role` | 必须为 `U` / `M` / `S`，与部署角色一致 |
| `protocol_version` | 主版本号不一致时平台标记 `compatible=false` 并在总控台告警（见 05 号文档） |
| `capabilities` | 节点能力集。缺 `fallback` 表示不支持预微调切换；缺 `eval` 表示不支持在线评测 |
| `assets` | 资产清单字符串数组，平台直接展示在三方页面 |
| `status` | `idle` / `busy` / `error` |

## 2. POST /v1/action —— 执行协议动作

平台编排器按阶段驱动。**这是唯一会触发真实计算/通信的接口。**

**请求**

```json
{
  "protocol_version": "1.0",
  "trace_id": "task_20260818093000_ab12",
  "stage": "BACKWARD",
  "step": 2,
  "action": "pir_query_mask",
  "params": { "auto": false }
}
```

| 字段 | 说明 |
| --- | --- |
| `trace_id` | 会话级追踪 ID（平台生成）。节点产生的所有日志/事件必须携带它 |
| `stage` | 阶段 ID，见下表 |
| `step` | 训练步序号（训练循环内 1..N；非训练阶段为 0） |
| `action` | 动作 ID。节点只需实现分配给本角色的动作 |
| `params` | 附加参数；节点应忽略不认识的键 |

**阶段-动作-角色矩阵**（与作品报告 Algorithm 1–3 对应）

| stage | action | 执行方 | 语义 |
| --- | --- | --- | --- |
| `INIT` | `bfv_keygen` | M | BFV.KeyGen，私钥不出域，公钥 pk_M 分发 U/S |
| `INIT` | `build_enc_db` | S | 构建 DB[j]=Enc_pkM(-W_j)（可用缓存） |
| `INIT` | `pir_prg_setup` | U | PIR 块协商 + 与 S 共享 PRG 种子 σ、计数器归零 |
| `DATA` | `load_dataset` | U | 装载 ClinVar 批次、本地分词（无跨方消息） |
| `DATA` | `register_task` | S | 登记任务、同步超参（batch/lr/rank/Δ/steps） |
| `FORWARD` | `local_embed` | U | 分词+嵌入+底部 Decoder → 发送 H_U（切线①） |
| `FORWARD` | `trunk_forward` | M | 顶部 Decoder+LoRA 前向 → 发送 H_M（切线②） |
| `FORWARD` | `head_forward` | S | z=H_M·Wᵀ, p=softmax, a_t=p_t·W；缓存 a_t；可选回 top-K |
| `BACKWARD` | `pir_query_mask` | U | 逐目标位置：派生 r_t → PIR 查询 → 掩码注入 → C_U 发 M |
| `BACKWARD` | `fetch_rows` | S | 块 PIR：按索引集合返回整块密文行（U 私有置换取行） |
| `BACKWARD` | `share_compute` | S | PIR 响应 + 计算 s_S = a_t - r_t 发 M |
| `INIT`/`BACKWARD` | `rms_parity` | S | RMS-PIR parity oracle：对行索引列表计算 BFV 密文和（离线 hints / 在线子集 / 补充半区共用） |
| `RECONSTRUCT` | `grad_reconstruct` | M | Dec(C_U)+s_S 重建 ĝ，校验并回报误差 |
| `UPDATE` | `lora_update` | M | 批量聚合 → LoRA 反向 → AdamW 更新 θ |
| `EVAL` | `open_eval` | S | 汇总产物、开放评测 |

**响应**（动作完成后返回；长耗时动作应同时通过 `/api/ingest` 推送中间进度）

```json
{
  "ok": true,
  "events": [
    { "type": "crypto", "payload": { "msg": "BFV.KeyGen 完成", "poly_degree": 4096 } },
    { "type": "message", "payload": { "msg": "公钥已分发", "edge": "M->S", "bytes": 32768, "hash": "0x…" } }
  ],
  "metrics": {
    "comm": [ { "edge": "M->U", "bytes": 32768 }, { "edge": "M->S", "bytes": 32768 } ],
    "loss": 1.9326,
    "grad_error": 2.1e-8,
    "step_ms": 12400
  },
  "result": { "key": "pk_M", "distributed_to": ["U", "S"] }
}
```

- `events[]`：有序事件数组，平台原样（脱敏后）广播到各页面。`type` 取值见 03 号文档。
- `metrics`：全部可选。`comm` 用于总控台通信量统计；`loss`/`grad_error` 用于收敛曲线与保真度展示。
- `result`：动作结果摘要，随 `action_done` 广播。
- **超时**：U/M 60s，S 120s（在 `platform.config.json` 可调）。超时平台标记动作失败并允许重试。

## 3. POST /v1/fallback/pretrained —— 备用方案：加载预微调检查点

当现场微调耗时不可控时，主持人在隐藏工程抽屉触发；平台依次调用 S → M → U。**节点收到后应加载事先微调好的 LoRA 检查点，使后续评测/推理基于该检查点进行。**

**请求**

```json
{
  "protocol_version": "1.0",
  "trace_id": "task_20260818093000_ab12",
  "checkpoint_id": "clinvar-tinyllama-lora-r8-20260815"
}
```

**响应**

```json
{ "ok": true, "checkpoint": "clinvar-tinyllama-lora-r8-20260815", "loaded": true, "load_ms": 830 }
```

- `checkpoint_id` 由平台 `config/platform.config.json → fallback.pretrained_checkpoint_id` 指定，**联调时三方须对该 ID 达成一致**。
- 节点加载失败返回 `ok:false` 并在 `error.message` 说明；平台会在总控台标红该节点，但不阻断其余节点。
- 详细预案见 `04-备用方案与降级预案.md`。

## 4. POST /v1/eval/run —— 评测接口

评测台的每个测试项目对应一个 `test_id`。平台默认向**测试注册的执行方**（多为 S）发起调用，**超时 300s**。

**请求**

```json
{ "protocol_version": "1.0", "trace_id": "task_…", "test_id": "acc", "params": {} }
```

**响应**

```json
{
  "ok": true,
  "result": {
    "status": "DONE",
    "metrics": [
      { "key": "before", "label": "微调前", "value": 61.2, "unit": "%" },
      { "key": "after",  "label": "微调后", "value": 88.5, "unit": "%" }
    ],
    "conclusion": "一句话结论（展示用）"
  }
}
```

- `status` 枚举：`DONE` / `PASS` / `PRIVACY_PRESERVED` / `VULNERABLE` / `BOUNDARY` / `INCONCLUSIVE`
- `metrics[]`：`key`（机器键）/ `label`（展示名）/ `value`（数字或字符串）/ `unit`
- 精度对比类测试约定 `key` 为 `before` / `after`，评测台自动渲染对比图。
- **已注册的 test_id 清单**见 `data/fixtures/eval-presets.json`（`dli_baseline`、`dli_triadft`、`l1`、`l2`、`m1`、`m2`、`eia`、`acc`、`auprc`、`macro_f1`、`grad_max_abs`、`grad_rel`、`step_time`、`comm`、`offline_db`）。节点至少应实现 `acc`/`auprc`/`macro_f1`（微调前后对比），其余可由平台预设数据回放。

## 5. 节点 → 平台：POST {platform}/api/ingest（进度推送）

长动作执行期间，节点可多次推送：

```json
{ "party": "U", "type": "pir", "stage": "BACKWARD", "payload": { "msg": "PIR 查询已发出", "query_id": "q_ab12", "edge": "U->S", "bytes": 145408 } }
```

平台鉴权：演示环境默认不鉴权；若需鉴权，在 05 号文档的扩展头中约定 `X-Node-Token`。

## 6. 脱敏铁律（必须遵守）

节点上报的 `msg`/`result`/`events` 中**禁止**出现：原始文本、真实标签、sk_M、PRG 种子、掩码向量明文、输出头行向量明文、模型权重。
只允许：样本/查询/掩码的 **ID 或哈希**、密文哈希与尺寸、耗时、误差、统计指标。
平台侧另有二次脱敏（`security.hidden_fields` 命中即替换为 `***`），但节点不得依赖平台兜底。
