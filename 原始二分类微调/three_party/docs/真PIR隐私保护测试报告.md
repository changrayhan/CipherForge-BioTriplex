# CipherForge 真 PIR 隐私保护测试报告

> 版本：真 PIR 版（2026-08-18 全量训练）。本报告回答两个问题：
> ① “S 获知监督位置、不获知标签值”到底是什么意思、为什么不算泄露？
> ② U 端的样本与标签是否泄露？

## 1. 一句话结论

**标签值（Yes/No 的 gold token）和原始变异文本永远只存在于 U 侧，从未离开
U；S 只收到两类信息：监督位置（答案在序列的哪两个位置）和 PIR 查询块
（一组密文行索引）。知道“答案在哪里”不等于知道“答案是什么”。**

## 2. 关键概念：监督位置 vs 标签值

### 2.1 监督位置是什么

因果语言模型按 next-token 方式训练：位置 t 的 logits 预测位置 t+1 的 token。
一条 ClinVar 样本在 token 化后是：

```text
question + input + "Answer:"   →  L 个 token（索引 0..L-1），不监督（-100）
" Yes" / " No"                →  2 个 token（索引 L、L+1），被监督
padding                       →  之后不监督（-100）
```

按 shift-by-one 对齐后，真正产生梯度的“监督位置”是：

- 位置 L−1（“Answer:”冒号）→ 监督目标是空格 token 29871；
- 位置 L（空格）→ 监督目标是 Yes 3869 / No 1939。

“监督位置”就是这两个索引（如某行是 `[69, 70]`）。它描述的是**标签在序列里
出现在哪里**，是模板结构决定的，不是敏感内容。

### 2.2 标签值是什么

标签值是每个监督位置上 gold token 的**具体取值**：3869 = “Yes”（致病）、
1939 = “No”（良性）。这是真正敏感的临床信息。

### 2.3 两者的区别

| 信息 | 例子 | 是否敏感 | 是否发给 S |
|---|---|---|:---:|
| 监督位置 | “第 69、70 个 token 是被监督的” | 低（模板结构） | 是（为性能） |
| 标签值 | “该样本是致病（Yes）” | 高（临床敏感） | **否（永不出 U）** |

**知道“答案在哪”≠ 知道“答案是什么”**：S 即使知道第 70 个位置是答案，
也不知道它是 Yes 还是 No——答案内容只存在于 U 的本地标签表里。

## 3. 真 PIR 如何保证 S 不知道标签

### 3.1 旧版（半诚实假设）的问题

旧实现把整张 `gold_ids`（含每个样本的 Yes/No 标签）发给 S，S 直接用它选择
密文行 `Enc(−V_y)`。这意味着 S 能看到每个样本的标签——这是“半诚实 S 可见
标签”假设。

### 3.2 新版（真块 PIR）的做法

```text
U（持有标签 y）
   │ 构建查询块：真实行 y + 7 个随机 dummy 行，随机置换（block=8）
   │ 只发送索引集合（不告诉 S 哪个是真实行）
   ▼
S（持有密文库）
   │ 返回整块 8 行密文（S 不知道哪一行是目标，猜中概率 1/8）
   ▼
U：按私有置换取回 Enc(−V_y)，同态加 r_t
S：另行生成 s_share = a_t − r_t（a_t 是模型预测的期望嵌入，与标签无关）
   ▼
M：解密 + s_share → 梯度 (a_t − V_y)·scale
```

- S 收到的是“一组行索引”，其中真实行被随机 dummy 稀释，**单个查询猜中
  概率 = 1/块大小 = 1/8**；
- S 计算的 `s_share = a_t − r_t` 完全标签无关：`a_t = softmax(z)·V` 来自
  模型自己的预测，不包含 gold 信息；
- 每个查询的 dummy 用 `secrets.SystemRandom` 独立采样，不同步/不同 token
  的查询块互不相关，S 无法跨查询关联出真实行。

### 3.3 改进版块 PIR（v2，2026-08-19 起默认）

v2 在保留“真实行 + dummy 行 + 私有置换”骨架的基础上做了三项增强：

1. **dummy 分布对齐真实分布**：dummy 不再从全词表均匀采样，而是按监督 token 的
   经验边际采样（本任务为 29871 空格 0.5、3869 Yes 0.25、1939 No 0.25，
   由 coordinator 从训练集标签计数得出，写入 `pir_dummy_weights`）。
   这样每个块内真实行与 dummy 行的边际分布一致，S 无法再用“哪一行频率异常高”
   来识别真实行。
2. **块大小 8 → 64**：`pir_block_size: 64`，位置级猜中概率降到 1/64。
3. **假查询块（真:假 = 8:2）**：`pir_fake_ratio: 0.25`，每 8 个真实块掺 2 个
   全假块（64 个 dummy 行、无真实目标），S 仍返回整块、U 丢弃结果；
   真假块统计不可区分，把真实查询的比例从 100% 压到 80%。

取行端同时做了**按唯一索引去重**：由于 dummy 集中在标签域，每步 10 个块约
640 个位置实际只覆盖 ~3-70 个唯一行，S→U 传输按唯一行计，单步密文传输从
名义 336 MB 降至 ~0.4-9 MB（实测 batch=4 时每步 ~0.4 s，首步含 mmap 加载
25.7 s）。

## 4. 泄露面审计：每方到底持有/看到什么

| 资产 | U（数据方） | M（模型方） | S（服务方） |
|---|:---:|:---:|:---:|
| 原始变异文本 / QA 数据 | ✅ 持有 | ❌ | ❌ |
| 标签值（Yes/No gold token） | ✅ 持有 | ❌ | ❌（只有监督位置） |
| 监督位置（答案索引） | ✅ | ❌ | ⚠️ 获知 |
| 明文输入序列 | ✅ | ❌（只有 H_U/H_M 隐状态） | ❌（只有 H_M） |
| 模型权重/LoRA | ❌ | ✅ | ❌ |
| BFV 私钥 sk_M | ❌ | ✅ | ❌ |
| V 矩阵（lm_head） | ❌ | ❌ | ✅ |
| 密文库 Enc(−V) | ❌（只拿到查询块密文） | ❌（只拿到掩码密文） | ✅ |
| PRG 种子 σ | ✅（与 S 共享） | ❌ | ✅（与 U 共享） |

**关键结论**：

1. **U 端样本与标签零泄露**：原始文本、标签值不进入任何跨方消息；U 只向外
   发送 H_U（隐状态）、PIR 查询块索引、掩码密文。
2. **S 不知标签值**：S 能看到的与标签相关的信息只有“监督位置”和“查询块”，
   二者都不含 Yes/No 取值。
3. **M 不知明文与标签**：M 只收到密文与 s_share。

## 5. 为什么不把监督位置也藏起来（性能权衡）

S 计算 `s_share` 需要知道给哪些位置算。两条路：

- **只算监督位置**（本版）：U 把位置索引发给 S，S 每步只算 32 个份额，
  步时 ~1.1s；
- **全部位置都算**：S 每步算 512 个份额，PRG（SHA-256）开销约 +2.5s/步，
  但 S 连监督位置也不知道。

监督位置是模板结构（答案固定跟在 “Answer:” 后），不是敏感内容；因此本版
选择“只算监督位置”以换取性能。若安全评审要求连位置也隐藏，可一键切换为
全位置计算（`share_positions=None`），隐私更强、速度更慢。

## 6. 实测验证数据

### 6.1 块 PIR 数学正确性（真实 SEAL）

| 测试 | 结果 |
|---|---:|
| 密文库完整性（14 行抽样解密） | 整数误差 0 |
| 完整往返（168 组，344,064 槽位，精确域） | max 误差 0.0001 |
| 完整往返（float32 传输） | max 误差 0.0035 |
| **块 PIR 往返（40 组 × block=8，81,920 槽位）** | **max 误差 0.0001** |

块取行、私有置换、掩码抵消在数学上与单行取回完全一致。

### 6.2 训练与测试

- 3 epochs × 625 步 = 1875 步，监控 CE 0.72 → 0.41，验证 token 准确率
  83.5~84.1%；
- 测试集 AUPRC **0.8033** / AUC **0.8081** / accuracy@0.5 0.6666；
- 明文基线 AUPRC 0.7922 / AUC 0.7936 / accuracy@0.5 0.722；
- 训练全程无 loss 尖峰、无 PIR 失败。

### 6.3 v2 改进的量化验证（频率攻击模拟 + 冒烟）

攻击模拟脚本：`scripts/pir_frequency_attack_sim.py`（纯统计模拟，dummy 采样
逻辑与 `PartyU._sample_pir_block` 一致）。攻击者已知标签域
{29871, 3869, 1939} 与采样分布 w，不知道哪些块是假块：

| 版本 | 真实查询数 | 行恢复率 | 全局 χ²（df=2） | 真假块判别 AUC |
|---|---:|---:|---:|---:|
| v1（均匀 dummy，block=8，无假块） | 32 | **100%** | 196.8 | — |
| v1 | 512 | **100%** | 3141.7 | — |
| v2（对齐 dummy，block=64，8:2 假块） | 32 | 40.6% | 0.1 | 0.543 |
| v2 | 128 | 42.2% | 1.4 | 0.498 |
| v2 | 512 | 38.7% | 5.1 | 0.541 |
| v2 | 2048 | 37.2% | 1.6 | 0.528 |

解读：

- v1 下 S 用 32 个块即可 **100%** 恢复每个查询的真实行（频率异常）；
- v2 下恢复率 ~38-42%，**接近 1/3 的随机水平**（标签域 3 个 token 的随机猜测）；
- 全局 χ² 远低于 0.05 显著性阈值（5.99），2048 个真实查询后仍无显著全局信号；
- 真假块判别 AUC ≈ 0.50-0.54，即 S **无法区分哪些请求是假块**。

诚实说明（残余风险）：

- v2 的有效单查询匿名集 = 标签域（3 个 token）：每个块都包含三者，S 对标签值的
  位置级猜中概率是 1/64，但若把“猜中标签值”作为目标，有效概率约 1/3（随机水平）；
- dummy 对齐只能压低、不能消除频率泄露：若真实标签比例严重不均衡，S 在极多
  步骤后仍可能通过全局计数检验察觉分布偏移；假块只贡献 20% 的稀释；
- 块 PIR（含 v2）不满足标准（有状态）PIR 的多查询隐私定义，跨查询交集分析
  仍是开放残余风险；需要标准隐私保证时切换到 RMS-PIR 备用方案（见
  `块PIR与S3PIR与RMS-PIR方案对比分析.md`）。

### 6.4 v2 冒烟测试（真实 SEAL + 真实密文库，三进程）

- 40 步 × batch=4（8 token/步），block=64、假块 8:2；
- 全部 fetch_rows / share_compute / grad_reconstruct 动作 ok=True，无 PIR 失败；
- 梯度真实（g_absmax≈5.37e4、g_meanabs≈365-424，与 v1 同量级），loss_ce 正常波动；

### 6.5 RMS-PIR 备用方案的验证（2026-08-19）

RMS-PIR（论文 Ren-Mughees-Sun CCS'24 两服务器变体）已作为 `pir_mode: "rms"`
备用模式实现，并升级为 **v2 职责划分**（U=offline server 持密文库副本、S=online
server 持明文 V），验证如下：

**真实 SEAL 往返验证（v2）**（`scripts/rms_roundtrip_verify.py`，加载真实
4.2 GB 密文库 + 明文 V + M 端私钥）：

- 初始 hint 与补充（replenished）hint 各 18 次查询，共 36 次；
- 每次恢复 `Enc(-V_y) = hint_parity ⊖ 真实子集 parity` 后解密，与直接取行
  解密逐槽比较：**max |误差| = 0.000000**（阈值 0.01）；
- 数学正确性：真实子集 + 假子集恰好覆盖全部 160 个分区、各 80 行；
  补充 hint 以 y 为额外索引、分布与消耗的 hint 一致；
- v2 位级一致性：hint parity 用 U 侧密文和（逐行 round 求和），在线子集 parity
  用 S 侧明文聚合+一次加密（同样逐行 round 求和），二者逐槽位一致，故误差为 0。

**三进程冒烟（v2）**（`three_party_config_rms.json`，12 步 × batch=4）：

- 密文库下载：4.20 GB / 89.9 s（U 端 `party_u/db/`，32MB 分块）；
- U 本地离线：2599 hints（M=2560 + 39 个确定性补足）构建 88.3 s；
- 全部 rms_parity / share_compute / grad_reconstruct 动作 ok=True，无 PIR 失败；
- 梯度真实且随训练增长（g_absmax 1.97 → 4.56），loss_ce 正常波动；
- 稳态步时 ~1.0-2.5 s（8 token/步）；
- **隐私验证**：S 日志中每步仅 1 次在线 `rms_parity`，全程无 hint/半区行列表
  请求——S 无可关联的 hint 状态，论文多查询隐私成立。

**诚实说明（v2 后的剩余事实）**：U 现在持有一份密文库加密副本（4.2GB，
pk_M 加密、U 无私钥不可解密；V 为公开权重，不构成新机密泄露）；“密文库只在
S”的隔离口径更新为“U 持加密副本、S 持原始库”。详见
`块PIR与S3PIR与RMS-PIR方案对比分析.md` §3.2.2 与 `04-备用方案与降级预案.md` §6。

## 7. 差分隐私模块（dχ-privacy，2026-08-19 迁入并默认开启）

### 7.1 模块与职责

- 模块：`shared/core/dchi_privacy.py`（从参考实现
  `CipherForgeCode/SLG-HE-PIR/src/core/dchi_privacy.py` 迁入），提供
  `H15Privatizer` 门面：多元拉普拉斯噪声 `DChiNoiseGenerator`、EMA 激活范数
  校准 `ActivationNormCalibrator`、标签条件贡献度 `LabelBasedCTI`、审计
  `PrivatizerAudit`；
- 注入点：U 端 `PartyU._maybe_privatize`，在 `H_U` 交给 M 之前注入噪声
  （train/val 都经过）；
- 参数：`dp_enable=true`、`dp_alpha=0.15`、`dp_eta0=900`（显式校准值）、
  `dp_answer_beta=0.5`（答案位置噪声放大 1/β）、`dp_num_classes=2`
  （ClinVar 二分类）。

### 7.2 ClinVar 适配（相对参考实现的两处修改）

1. **batch 键映射**：三进程训练 batch 用 `output_ids`（token id，-100 忽略），
   参考实现读 `labels`。`_maybe_privatize` 现在把答案 token 映射为二分类标签
   （Yes=1 / No=0，其余 -100）再传给 `H15Privatizer`，使 CTI 与答案位置
   大噪声语义正确生效；
2. **性能修复**：噪声半径原实现是 `for _ in range(d)` 逐个 `exponential_`
   （每位置 2048 次 CUDA 往返，实测 ~15s/步）；改为单次 `exponential_` 向量化
   求和（分布完全一致，Gamma(d, η)，保留私有 generator），稳态 ~0.4s/步。

### 7.3 冒烟验证（真实 SEAL + 三进程，20 步 × batch=4）

- `[PartyU] H15 privatizer attached (alpha=0.15, beta=0.5)` —— 模块加载成功，
  不再出现 `import failed` 警告；
- `[PartyU] DP activated: eta_ctx=900 eta_ans=450 noise_l2_ctx=2.29
  noise_l2_ans=3.51` —— 噪声按 η0=900 注入（上下文 L2≈2.3、答案位置 β=0.5
  放大至 L2≈3.5）；
- 训练 20 步全部完成：loss_ce 0.4-1.9 正常波动（比无 DP 略高，符合噪声-效用
  权衡），g_absmax≈5.37e4 与无 DP 同量级，无 NaN、无 PIR/密文错误；
- 稳态步时 ~0.4-0.8s（首步 34s 为 CUDA 生成器与噪声路径首次初始化）。

### 7.4 诚实说明（使用边界）

- `dp_eta0=900` 为**显式校准值**（替代参考实现的 EMA 校准回退），对应
  相对噪声 ‖n‖/A ≈ 2.3/典型激活范数；正式使用前建议用
  `dp_calibration_mode=true` + `dp_calibration_steps` 在校准集上重估 η0
  （当前协调器尚未内置“校准后自动切换”的运行时开关）；
- DP 注入在 BFV 明文域之前（H_U 出 U 前加噪），加噪幅度需保证
  plain_modulus 余量（scale=10000、plain_bits=30 余量充足，冒烟已覆盖）；
- 加噪会降低收敛精度，正式训练前应重新标定超参与期望 AUPRC。

## 7. 结论

1. **S 获知监督位置 ≠ S 知道标签**：前者是“答案在哪里”，后者是“答案是什么”。
2. **U 端样本与标签零泄露**：原始文本与标签值只存在于 U，不进入任何跨方
   消息；向外只发隐状态、查询块与密文。
3. 真 PIR 使 S 对每个查询的目标行猜中概率降为 1/8，且 s_share 计算标签无关；
   相比旧版“S 半诚实可见标签”，隐私语义严格增强。
