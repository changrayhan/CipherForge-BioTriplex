# 01 · 平台架构说明

## 1. 定位

演枢台部署在演示笔记本上，**只编排、只展示、不计算**。三方真实计算在三台服务器的 U/M/S 节点上完成；平台通过 HTTP 下发阶段动作、通过事件流回收状态并驱动五个页面。

```
┌──────────────────────── 演示笔记本（演枢台）────────────────────────┐
│  web/pages:  master(总控)  party-u  party-m  party-s  eval(评测台)   │
│       ▲ SSE 事件流 /shared/js/bus.js                                │
│  server/routes:  api.js(REST)  stream.js(SSE)  static.js            │
│  server/core:    orchestrator(阶段编排)  state(状态机)               │
│                  eventbus(事件总线+脱敏)  modes(双模式)              │
│  server/adapters: remote.js(HTTP客户端)  local.js(三方模拟器)        │
└───────────────┬──────────────┬──────────────┬─────────────────────┘
                │ HTTP/JSON    │              │
        ┌───────▼─────┐ ┌──────▼──────┐ ┌─────▼───────┐
        │ U 节点 :9001 │ │ M 节点 :9002 │ │ S 节点 :9003 │
        │ 医院/数据    │ │ 药企/模型    │ │ 监管/服务    │
        └─────────────┘ └─────────────┘ └─────────────┘
```

## 2. 关键设计决策

| 决策 | 理由 |
| --- | --- |
| 零第三方依赖（Node 原生 http/SSE/fetch） | 演示日 `node server/index.js` 即可运行；无 npm 安装失败风险 |
| SSE 而非 WebSocket | 事件流是单向广播（平台→页面），SSE 更简单且自动重连；页面→平台走 REST |
| 多页应用（每方独立页） | 三方屏幕各开一个页面；职责隔离，符合"微服务式"结构诉求 |
| 阶段状态机 + 动作门控 | 每阶段声明所需三方动作（`state.js STAGES`），轮到谁操作一目了然；动作完成自动推进 |
| 双模式适配器同接口 | `remote.js` 与 `local.js` 实现同一接口（`adapters/base.js`），模式切换只换适配器，编排器无感知 |
| 事件脱敏在总线层 | `eventbus.js` 统一把 `security.hidden_fields` 替换为 `***`，页面永远接触不到敏感字段 |
| 评测注册表外置 JSON | 测试项目增删改不改代码（`data/fixtures/eval-presets.json`），远程模式按 `test_id` 调节点 |

## 3. 阶段编排

`INIT → DATA → [FORWARD → BACKWARD → RECONSTRUCT → UPDATE] × N步 → EVAL`

- **手动驱动（默认）**：阶段推进后，对应方页面出现待办操作卡，点击执行；总控台显示"轮到 X 方操作"。
- **自动驱动（隐藏）**：编排器依次自动执行各动作，用于无人值守兜底。
- 阶段全部动作完成 → 1.2s 后自动进入下一阶段（训练循环内自动步进）。
- 总控台可强制推进/跳过阶段；工程抽屉可中止会话、平台复位。

## 4. 状态与事件流

- 单一事实来源：`server/core/state.js` 的 `StateStore`；所有变更经 `patch()` 发出 `state` 事件。
- 事件历史环形保留 800 条，新打开页面通过 SSE 订阅自动回放，随时可恢复现场。
- 节点上报的 `metrics`（comm/loss/grad_error/step_ms）汇入 `state.metrics`，驱动总控台统计与收敛曲线。

## 5. 三方页面职责

| 页面 | 展示重点 |
| --- | --- |
| party-u（医院） | 数据与嵌入资产、"原始文本与标签不出域"不变式、PIR 查询与掩码注入操作 |
| party-m（药企） | 主干+LoRA 资产、BFV 私钥封存、梯度重建误差校验、LoRA 更新 |
| party-s（监管） | 任务登记、输出头与密文数据库、PIR 响应、份额计算、评测入口 |
| master（总控） | 阶段时间线、三方拓扑与数据流粒子、分通道通信量、loss 曲线、审计事件流 |
| eval（评测台） | 精度（前后对比）/ 攻击（DLI、L-1/L-2、M-1/M-2、EIA）/ 保真度 / 性能，自定义测试注册 |

## 6. 演示数值口径

- 演示配置：TinyLlama-1.1B + ClinVar（P/LP vs B/LB）+ LoRA r=8 + BFV-4096，训练 3 步，目标总时长 1–2 分钟。
- 本地演示模式的数值为按该配置合成的拟真值；真实模式数值全部由节点实测返回。
- 评测台"参考值"（8B/101s、15.67GB、2.24e-8 等）来自作品报告与 TriadFT 论文，已在文案中标注来源。
