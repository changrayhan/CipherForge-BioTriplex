# 00 · 交付清单与部署指南（先读）

## 1. 交给服务器开发的文档

把以下三份（+ 本份）打包发给三台服务器的开发同学：

| 文档 | 对方要做什么 |
| --- | --- |
| `02-节点接口规范.md` | **核心**。在 U/M/S 节点实现 `/v1/hello`、`/v1/action`、`/v1/fallback/pretrained`、`/v1/eval/run` |
| `03-通信协议与消息格式.md` | 按事件类型表上报 `events`/`metrics`；按 edge 表标记跨方消息；遵守脱敏铁律 |
| `04-备用方案与降级预案.md` | 实现预微调检查点加载；准备彩排检查点并与平台统一 `checkpoint_id` |
| `05-兼容性与扩展性约定.md` | 了解版本协商与变更流程，联调变更按此走 |

另请把 `config/platform.config.json` 中 `nodes.U/M/S.url` 的实际地址与对方确认后填入。

## 2. 联调步骤

1. **节点自检**：三台服务器各自启动节点，确认 `curl http://<node>:<port>/v1/hello` 返回 `ok:true`。
2. **改配置**：编辑 `demo/config/platform.config.json` → `nodes.*.url` 指向三台服务器；确认 `platform.mode = "remote"`。
3. **启动平台**：`node server/index.js`，总控台右上角徽标应显示「真实通信模式」，点「节点探活」三方全绿。
4. **空跑**：开始会话，逐阶段执行。INIT/DATA 通过后说明握手、密钥分发、任务登记链路正常。
5. **单步跑通**：FORWARD→BACKWARD→RECONSTRUCT→UPDATE 完整一步，核对总控台通信量、loss、梯度误差是否合理。
6. **评测联调**：评测台先跑 `acc`（必须实现），其余测试可先靠预设回放，逐步实现。
7. **备用方案演练**：触发一次「跳过训练」，确认三方正确加载检查点、评测 after 侧数据来自检查点。

## 4. 平台配置速查（platform.config.json）

| 键 | 说明 |
| --- | --- |
| `platform.mode` | `remote`（默认真实通信）/ `local`（本地演示兜底） |
| `platform.port` | 平台端口，默认 8600 |
| `nodes.*.url` / `timeout_ms` | 三方节点地址与超时 |
| `demo.train_steps` | 演示训练步数（默认 3） |
| `fallback.pretrained_checkpoint_id` | 与三方约定的预微调检查点 ID |
| `security.hidden_fields` | 平台二次脱敏字段清单 |

## 5. 常见问题

- **端口被占**：改 `platform.port` 或释放 8600。
- **节点离线（红）**：确认服务器安全组/防火墙放行对应端口；平台与服务器网络可达。
- **动作超时**：调大 `timeout_ms`；或在节点侧把长操作改为"先返回 + /api/ingest 推送进度"。
- **误操作**：工程抽屉（连击印章 5 次）→「平台复位」即可清空状态重来。
