## 2. 变更内容一句话

RMS-PIR 备用方案升级为 **v2 职责划分**：

- **U 端（offline server）**：一次性下载 S 的密文库副本（4.2GB，Enc(-V)，pk_M
  加密，U 不可解密）到 `party_u/db/`；U 本地构建 hint parity 与每查询的
  补充半区 parity —— **S 永远看不到 hint 子集与半区**；
- **S 端（online server）**：只应答在线查询的两个子集 parity，采用
  **明文聚合（逐行 round(V·scale) 整数求和）+ 一次 BFV 加密**，与密文求和
  位级一致、速度更快；S 在 RMS 模式下不再加载 4.2GB 密文库；
- 效果：RMS-PIR 获得论文标准（有状态）PIR 的**多查询隐私**（S 无法关联
  hint 与查询，Lemma 2 + §3.5 成立），不再依赖“S 不进行关联”假设。

## 4. 替换后的验证步骤（在目标设备上）

```bash
# 1) 依赖与模型同《三进程版从零部署与交接手册》
export CF_MODEL_PATH=/path/to/tinyllama-snapshot
export PYTHON=$(which python)

# 2) 真实 SEAL 往返验证（约 1-2 分钟；需 party_m/keys 与 party_s/db 已有）
cd three_party
python -u scripts/rms_roundtrip_verify.py --keys_dir party_m/keys \
  --db_dir party_s/db --model_path $CF_MODEL_PATH --lam 12
# 期望输出: [roundtrip] OK: 36 queries, max |err| = 0.000000

# 3) 三进程冒烟（RMS v2 模式；首次会自动下载 4.2GB 密文库到 party_u/db/）
export REPO_ROOT=$(pwd) PYTHONPATH=$(pwd) HF_HUB_OFFLINE=1
python -u -s party_s/main_s.py --port 9003 --db_dir party_s/db --device cpu &
python -u -s party_m/main_m.py --port 9002 --keys_dir party_m/keys &
sleep 4
python -u -s coordinator/main.py \
  --config coordinator/three_party_config_rms.json \
  --max_train_steps 12 --batch_size 4 --log_freq 4
```

预期：日志出现 `RMS v2: encrypted DB downloaded ... (4.20 GB)`、
`RMS v2 offline (U-local): ... hints ... built`；训练 12 步无 PIR 错误，
`g_absmax` 随步增长；S 日志中只有在线 `rms_parity`（每步 1 次），
**不再出现任何 hint/半区行列表请求**。

## 5. 注意（不要覆盖/不要手动改）

- `party_u/db/bfv_ct_db_n32000_d2048_p4096.bin`：**运行时生成**（4.2GB，
  由 S 分块下发），不入 Git（已加入 `.gitignore`），无需也不能从仓库拉取；
- `party_m/keys/`、`party_s/db/`、`party_m/checkpoints/`、`coordinator/adapter/`
  均为运行产物/密钥，不入 Git；新设备首次运行会自动生成密钥与密文库（约 1 小时），
  或从已有设备拷贝复用；
- BFV 参数（`poly_degree/plain_bits/scale`）与密文库绑定，禁止改动；
- 若只跑默认块 PIR v2，本变更不改变任何行为（`pir_mode` 默认仍为 `block`）；
  RMS v2 仅在使用 `three_party_config_rms.json`（或 `--pir_mode rms`）时生效。
